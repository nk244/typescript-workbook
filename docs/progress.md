## 教材側の宿題

採点していて気づいた、教材そのものの穴。

- **演習 3-4 のテストが弱い** — テストが `bark: () => 'ワン'` を渡しているので、
  `animal.bark()` を呼ばず `'ワン'` を直書きしても通ってしまう。
  戻り値を `'ワンワン'` などに変えれば、絞り込んで呼ばない限り落ちるようになる。
- **演習 7-3 の「override を付けること」がテストで検出されない** — `noImplicitOverride` は
  `abstract` メソッドの実装には `override` を強制しないので、付け忘れても `npm run check` が通る。
  クラスの `area` が `override` で宣言されているかを確かめる手段を足すか、設問を「推奨」に弱める。
- **演習 10-6・10-7 が未習の前提に頼っていた**（2026-10-05 に修正済み） — 10-6 は第16章で扱う Promise を
  説明なしに出題し、10-7 は「createUser を実装しろ」だけで返すべき値が読み取れなかった。
  第10章 README に Promise 入門を足し、10-7 の設問に各プロパティの出どころと入出力例を補った。

## 記録の付け方

```bash
npm run check 04        # 緑になったら採点して、この表の 04 の行を埋める
```

テスト数は採点時の `Tests N passed` の N。型レベルだけの演習は実行時テストを持たないので、
`✅ 型チェック OK` が答え合わせそのものになる（第12章など）。

**採点は緑になった直後にやること。** 何点だったかより、
「なぜ引かれたか」を一行で書き残すほうが効く。

採点のとき、その章で学習者が **つまずいた点・した質問・した指摘** も
「つまずき・質問・指摘の記録」の表に足す。点数が高くても、詰まった箇所は後で効く。
