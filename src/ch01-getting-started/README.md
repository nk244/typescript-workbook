# 第1章 TypeScript とは何か / 最初の型

## この章のゴール

- TypeScript が「何をしてくれる言語」なのかを、JavaScript との差分で説明できる
- `tsc` が何をしているのか（型チェックとトランスパイルは別物）を理解する
- 型注釈を書き、わざとエラーを出して読み解ける

---

## 1. TypeScript は「JavaScript + 静的型」

TypeScript は JavaScript のスーパーセットです。つまり **正しい JavaScript は、そのまま正しい TypeScript**（設定次第）。
足されているのは基本的に次の 2 つだけです。

1. **型注釈**（`const n: number = 1`）という構文
2. **コンパイル時の型チェック**

そして重要なのが、**型は実行時には 1 バイトも残らない**ことです。

```ts
const age: number = 30;
```

これをコンパイルすると、出力される JavaScript はこうなります。

```js
const age = 30;
```

型注釈はきれいに消えます。TypeScript の型は「実行時の値を守る鎧」ではなく、
**書いている最中にコンパイラと交わす約束**です。だから

- 型を書けば実行速度が上がる → **上がらない**
- 型があれば実行時エラーが起きない → **起きる**（外部から来たデータは嘘をつく。第17章で扱います）

という点は最初に押さえておいてください。

## 2. `tsc` がやっている 2 つの仕事

`tsc`（TypeScript Compiler）の仕事は独立した 2 つです。

| 仕事 | 内容 | 止められるか |
| --- | --- | --- |
| 型チェック | 型の矛盾を探して報告する | `--noEmit` で「チェックだけ」にできる |
| トランスパイル | 型を消して .js を出力する | 型エラーがあっても **出力はされる**（既定） |

「型エラーがあるのに動く」のはこのためです。型エラーは**警告の一種**であって、実行の妨げではありません。
（`noEmitOnError` で止めることもできます。第18章）

このリポジトリでは `"noEmit": true` にしてあります。学習中は「型が通るか」だけを見ればよいからです。

## 3. 型注釈と型推論

TypeScript は、書かなくても型を推論します。

```ts
let a = 10;          // a: number と推論される
let b = 'hello';     // b: string
const c = 10;        // c: 10   ← const は「リテラル型」まで狭く推論される
```

`let` は再代入されうるので `number` まで広げ、`const` は変わらないので `10` という
**その値ちょうどの型（リテラル型）** に推論されます。この違いは第5章の `as const` で効いてきます。

**原則: 推論できるところに型注釈は書かない。** 冗長になるうえ、実装を変えたときに嘘になりやすいからです。
逆に、**書くべき場所は「境界」** です。

```ts
// 関数の引数は推論できない（＝必ず書く）
// 戻り値は推論できるが、公開する関数では明示すると「実装ミスをその場で検出」できる
function double(n: number): number {
  return n * 2;
}
```

## 4. エラーメッセージの読み方

TypeScript のエラーは長いですが、構造は毎回同じです。

```
Type 'string' is not assignable to type 'number'.
     ^^^^^^                            ^^^^^^
     実際に渡ってきたもの                期待されているもの
```

「**assignable（代入可能）** かどうか」がすべての基準です。TypeScript の型の善し悪しは、
「A を B の場所に置いてよいか」という一点で決まります。この感覚は第14章で構造的部分型として体系化します。
